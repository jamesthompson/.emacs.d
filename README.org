* .emacs.d

My Emacs configuration. Emacs 30 on macOS, built with native compilation,
run as a terminal daemon under launchd and attached with =emacsclient -t=.
Setting that up from scratch is below.

** Layout

| path          | purpose                                            |
|---------------+----------------------------------------------------|
| early-init.el | GC threshold and frame setup, before packages load |
| init.el       | everything else                                    |
| lisps/        | packages on no archive, currently just ats-mode    |
| custom.el     | customize output, untracked                        |
| env-cache.el  | cached shell environment, generated, untracked     |
| tree-sitter/  | compiled grammars, generated, untracked            |

Packages come from MELPA through =package.el= and are configured with
=use-package= throughout. UI packages load at startup. Language and tool
modes defer until a matching file is opened.

** Requirements

| what          | needed for                         |
|---------------+------------------------------------|
| emacs-plus@30 | Emacs 30.2 with native compilation |
| git and cc    | building tree-sitter grammars      |
| rg            | deadgrep                           |
| direnv        | envrc                              |
| gopls         | Go LSP                             |
| pgformatter   | sqlformat                          |

The tree-sitter modes themselves arrived in Emacs 29, so the config loads on
29 as well; it is written against 30.

** Setting up on macOS

*** The Emacs build

Homebrew core's =emacs= depends on gmp, gnutls and tree-sitter and on no
version depends on libgccjit, so it cannot be built with native compilation.
This config expects =emacs-plus@30=, which pins the same Emacs 30.2 by
checksum and hardcodes =--with-native-compilation=aot=.

#+begin_src sh
brew tap d12frosted/emacs-plus
brew trust d12frosted/emacs-plus
brew install emacs-plus@30
#+end_src

Homebrew 7 refuses to load a formula from an untrusted tap, which is what the
=brew trust= line is for. The install pulls gcc, libgccjit and the librsvg
graphics stack, all bottled.

If core =emacs= is already installed the link step fails, because it owns the
shared paths under =share/emacs=. Unlink it rather than uninstalling, so
going back is two commands:

#+begin_src sh
brew unlink emacs
brew link emacs-plus@30
#+end_src

*** The daemon

=brew services= cannot start this formula. It reports =has not implemented
#plist, #service or provided a locatable service file=, although the formula
does have a =service= block and =brew services info= resolves the label.
Write the launchd job yourself, as
=~/Library/LaunchAgents/sh.brew.emacs-plus@30.plist=:

#+begin_src xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>sh.brew.emacs-plus@30</string>
  <key>LimitLoadToSessionType</key>
  <array>
    <string>Aqua</string>
    <string>Background</string>
    <string>LoginWindow</string>
    <string>StandardIO</string>
    <string>System</string>
  </array>
  <key>ProgramArguments</key>
  <array>
    <string>/opt/homebrew/opt/emacs-plus@30/bin/emacs</string>
    <string>--fg-daemon</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardOutPath</key>
  <string>/opt/homebrew/var/log/emacs-plus@30.stdout.log</string>
  <key>StandardErrorPath</key>
  <string>/opt/homebrew/var/log/emacs-plus@30.stderr.log</string>
</dict>
</plist>
#+end_src

=KeepAlive= is =true= rather than the formula's =crashed: true=, so the
daemon also comes back from a deliberate =M-x kill-emacs=. Start it with:

#+begin_src sh
mkdir -p /opt/homebrew/var/log
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/sh.brew.emacs-plus@30.plist
#+end_src

Restarting it afterwards, in place of =brew services restart emacs=:

#+begin_src sh
launchctl kickstart -k gui/$(id -u)/sh.brew.emacs-plus@30
#+end_src

Startup errors land in the =StandardErrorPath= log above.

*** First run

The first start downloads every package from MELPA, so give it a minute or
two. Native compilation then runs in the background, filling
=~/.emacs.d/eln-cache= as each file is loaded for the first time. It keeps
growing for a while and settles in the low hundreds of files and tens of
megabytes. Both =elpa/= and =eln-cache/= persist and are untracked.

Build the tree-sitter grammars once the daemon is up, then check it over:

#+begin_src sh
emacsclient -e '(native-comp-available-p)'          # t
emacsclient -e '(length major-mode-remap-alist)'    # 7, once grammars are built
#+end_src

Attach with =emacsclient -t=. Nothing here needs a GUI frame, though
emacs-plus builds =Emacs.app= anyway.

*** Rolling back

The core formula is still installed if it was only unlinked:

#+begin_src sh
launchctl bootout gui/$(id -u)/sh.brew.emacs-plus@30
brew unlink emacs-plus@30 && brew link emacs
brew services start emacs
#+end_src

** Shell environment

Under launchd the daemon inherits only =/usr/bin:/bin:/usr/sbin:/sbin=, so
the shell environment is imported once and cached in =env-cache.el=. The
cache rebuilds itself whenever =~/.zshenv=, =~/.zprofile= or =~/.zshrc=
changes. If a tool reaches =PATH= some other way, run =M-x env-cache-refresh=.

** Tree-sitter

Six languages use the tree-sitter modes built into Emacs 30 rather than the
regex ones. A grammar is a shared library that has to be compiled on the
machine, and none ship with Emacs, so on a new machine run:

: M-x treesit-install-grammars

That builds every grammar in =treesit-language-source-alist= into
=~/.emacs.d/tree-sitter=, skipping any already present. A prefix argument
rebuilds those too. Currently go, gomod, json, yaml, rust, typescript, tsx
and dockerfile.

=major-mode-remap-alist= is populated only for grammars that are actually
built. A tree-sitter mode cannot start without its grammar, so a machine that
has not run the install falls back to =go-mode=, =json-mode= and the rest
rather than failing to open the file.

** Core packages

| area       | packages                                                     |
|------------+--------------------------------------------------------------|
| appearance | doom-themes, doom-modeline, diminish                         |
| completion | ido + flx-ido, ido-vertical, ido-completing-read+, company   |

| editing    | expand-region, paredit, aggressive-indent, string-inflection |

| runtime    | gcmh                                                         |

=display-line-numbers-mode= and =rainbow-delimiters= are on =prog-mode-hook=.
=aggressive-indent= is lisp only, since it reindents on every change. In ido,
=C-n=, =C-p= and the arrow keys step through matches rather than history.

** Keys worth knowing

Standard bindings are left alone unless listed here.

| key     | command                                        |
|---------+------------------------------------------------|
| C-x m   | magit-status                                   |
| C-x o   | find-file-in-project                           |
| C-x f   | recent files                                   |
| C-x g l | goto-line                                      |
| C-x -   | toggle a two-window split between rows/columns |
| C-x C-j | dired-jump                                     |
| C-x C-r | rename the current file and buffer             |
| C-x C-c | delete-frame, not quit                         |
| C-x r q | actually quit                                  |
| M-x     | smex                                           |
| M-h     | kill region, or the word before point          |
| C-c n   | expand-region                                  |
| C-c N   | untabify, strip whitespace, reindent buffer    |
| C-c i   | indent-region                                  |
| C-c e   | company-complete                               |
| C-c E   | hippie-expand, case sensitive                  |
| C-c G   | deadgrep                                       |
| C-c b   | new scratch buffer                             |
| C-c c   | comment or uncomment region                    |
| C-c +   | increment the number at point                  |

=C-h= is backspace, so help moves to =C-H=. =C-i= is left alone, because in a
terminal it is =TAB=.
